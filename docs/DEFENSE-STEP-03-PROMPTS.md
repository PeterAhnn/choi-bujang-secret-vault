출처: https://aleph-omega.vercel.app/defense 로그인된3단계 창. 확인일:2026-10-06 한국 시간. 표시된 본문을 직접 대조했으며 입력 칸은 원문 그대로 보존한다. 실행 결과는 별도 단계 기록에 남긴다.

## 이어받기

이 폴더는 1~2단계까지 만든 같은 자료실이야. 이번에는 3단계 「진짜 로그인을 붙입니다」를 할 거야. AGENTS.md와 README.md, 폴더 구조, git 상태, git log -1을 읽고 README의 단계 기록이 마지막 커밋과 맞는지 대조해 줘. 어긋나면 먼저 알려 줘. 현재 기능을 다섯 줄 이내로 요약하고 다른 작업은 보존해. 아직 아무 파일도 고치지 마.

## 만들기 1: 제작 1

같은 자료실에 Supabase Auth 이메일·비밀번호 로그인·로그아웃 화면만 붙여 줘. Project URL은 [ ], publishable key는 [ ]야(둘 다 공개용이라 화면 코드에 넣어도 돼). 공식 SDK 흐름을 쓰고 비밀번호·JWT를 직접 만들지 마. 로그인 실패는 화면에 이유를 보여 줘.

확인: A 계정 로그인과 로그아웃 후 화면 상태가 달라야 합니다.

## 만들기 2: 제작 2

자료 API에서 틀의 src/verify-login.mjs 로 요청 토큰을 검사해 줘. 도우미를 고치거나 새로 만들지 마. 브라우저가 보낸 userId·role은 믿지 마. 토큰이 없거나 검사에 실패하면 자료 없이 거부하고, 정상 A 로그인은 유지해 줘. 검사에 쓴 발급자 정보를 aleph.config.json의 identityProvider에 적어 줘(비밀 키 제외).

확인: 시크릿 창에서 로그인 없이 자료가 안 보이고 정상 A 로그인 뒤에는 보여야 합니다.

## 만들기 3: 제작 3

로그인한 사람이 가상 메모를 추가·수정·삭제하는 화면과 서버 API를 붙여 줘. 서버가 확인한 사용자 ID로 로그인 여부를 검사하고, 추가할 때는 그 ID를 owner_id로 저장해. 실제 GET·POST·PUT·DELETE 경로를 aleph.config.json의 allowedRoutes에 적어 줘. 아직 소유자 검사는 하지 않아서 B가 A의 메모를 고칠 수 있는데, 그 허점은 4단계에서 고칠 거야. API는 이 모양으로 해 줘 — POST는 {id,title,body}(id는 UUID, 없으면 서버가 만들어 {id}로 돌려줘), GET·PUT·DELETE는 /:id로, 한 건 GET 응답은 {id,title,body}, 지운 뒤 GET은 404. 목록 GET은 로그인 사용자의 메모 배열을 돌려줘.

확인: A가 메모를 추가·수정·삭제할 수 있고 무로그인 요청은 거부되어야 합니다. B의 타인 메모 접근 여부는 4단계에서 기록합니다.
