## 비교와 실제 실패 원인

두 현재 작업본은 각각 입력의 loading/ok/error, demo/disconnected/unknown, 한국어 뜻과 원래 상태 코드, 새 DOM 반환과 오류 후 이전 값 제거, createElement·textContent 안전한 출력을 구현했다. A는 현재 사용자·기기·세션을 묶고 목록을 별도 표시하며, B는 계정·기기·세션 구역으로 나눈다. B에는 계약 불일치·검증 불가 오류를 구분하는 설명도 있다. 코드 스타일을 근거 없이 우열로 판정하지 않았다.

두 현재 작업본의 문법 검사와 Node.js 간이 모의 DOM 비교 각 36/36이 통과했고, 검사 중 추가 요청은 0건이었다. 실제 브라우저 검사가 아니며 이 비교 검사 스크립트·결과 파일은 미보관이고 도구 실행 기록만 있다. 기존 A의 41건 실제 브라우저 DOM 검사와 이번 검사를 구분한다.

포털 상태를 한 번 갱신한 결과, 가장 최근 제출은 2026-10-23 11:19·커밋 99a10e59c25f였다. student-source-changed, student-identity-updates, student-failure-visible, identity-after-reload가 실패했고 three-menus만 통과했다. 공식 설명은 renderIdentity가 입력을 사용하지 않고 구현 대기 문구만 반환한다고 명시했다. 이 원문은 B의 HEAD와 일치하며 현재 미커밋 작업본과 다르다. Workbench 화면에도 제출 준비는 커밋된 HEAD만 전달한다고 명시돼 있다. 따라서 구현 누락을 추측해 다시 코드를 고칠 문제가 아니라, 구현되지 않은 옛 커밋을 제출한 문제다.

공식 원문 도구의 --commit 옵션으로 해당 커밋을 내보냈다. 627808바이트이며 SHA-256은 267e2a4a8c0ef968a4efd393b556fee9ec4ef038454cf643566a414c9187488f다. 2026-10-19 공식 통과 제출 원문과 크기·해시가 완전히 같다. 기존 HEAD·학생 코드·Git 기록을 변경하지 않았다.

2026-10-23 11:35 저장소 주소·전체 커밋·동일 원문으로 재접수했고 '원문 전달을 확인했습니다'를 확인했다. 재제출은 이번 요청에서 1회다. 접수 후 5분 이내에 공식 재통과를 확인했다. student-source-changed, three-menus, student-identity-updates, student-failure-visible, identity-after-reload가 모두 통과다. 포털이 이번 제출의 처음 통과한 접수 시각을 2026-10-23 11:35로 표시하므로, 2026-10-19 이력과 구분한다. 통과 확인 뒤 판정 대기와 추가 조회는 종료했다.

## Workbench 진행 프롬프트

Workbench의 기존 대화에는 시작 안내의 첫 요청과 13단계 상세 원문이 이미 입력돼 있었다. 같은 대화에 현재 두 저장소·미커밋 제출 실패의 구체 원인과 앞으로의 진행 규칙을 담은 프롬프트를 입력하고 전송했다. 원문은 [WORKBENCH-PROGRESS-PROMPT.md](WORKBENCH-PROGRESS-PROMPT.md)에 보관한다.

현재 프로젝트를 읽기만 하고, 폴더·기록·학생 코드를 변경하지 않은 채 다음 14단계 원문을 받을 준비를 설명하도록 요청했다. 14~16단계를 B에서 구현했다고 주장하지 않고 A와 B의 완료 상태를 구분하도록 명시했다. Git 실행이 불가능한 Workbench의 한계를 유지하며, 커밋·제출은 실제 실행 결과와 원문 일치 확인 후 처리하도록 했다.

첫 응답은 파일 목록·시작 안내·학생 구현을 읽고 13단계 구현과 14단계 이후 기본 문구를 구분했지만 file_path 도구 오류 한 건 때문에 정상 완료로 처리되지 않았다고 표시됐다. 이를 전체 도구 성공으로 기록하지 않았다. 구체적인 외부 저장소 확인은 하지 못했다는 응답을 보존한다. 후속 프롬프트로 외부 확인은 Codex가 전달한 결과라고 표시하고, 새 도구 호출·파일 수정 없이 진행 규칙 적용과 14단계 최신 원문 대기를 확인하도록 요청했다. Workbench는 이 구분을 수용하고 실제로 원문 대기를 응답했다. B의 Git 상태는 기존 on-client/student/extension.mjs 미커밋 변경만 유지한다. 이번 작업에서 B 코드를 수정하거나 커밋하지 않았다.

이번 작업의 근거 파일은 Git에서 제외되는 .local/step13-compare-2026-10-23에 보관한다. 새 사용자 직접 확인이나 공식 통과 결과를 만들지 않는다.
