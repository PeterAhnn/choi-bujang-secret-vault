출처: https://aleph-omega.vercel.app/defense 로그인된5단계 창. 확인일:2026-10-06 한국 시간.

## 이어받기

이 폴더는 1~4단계까지 만든 같은 자료실이야. 이번에는 5단계 「자료 요청을 서버 한곳으로 모읍니다」를 할 거야. AGENTS.md와 README.md, 폴더 구조, git 상태, git log -1을 읽고 README의 단계 기록이 마지막 커밋과 맞는지 대조해 줘. 어긋나면 먼저 알려 줘. 현재 기능을 다섯 줄 이내로 요약하고 다른 작업은 보존해. 아직 아무 파일도 고치지 마.

## 만들기 1: 제작 1

브라우저 코드가 메모 자료를 Supabase에서 직접 읽거나 고치는 곳이 있는지 찾아 줘. 있으면 서버 함수 호출로 바꾸고, 없으면 '없음'이라고만 알려 주고 아무것도 고치지 마. 로그인(Auth) 호출은 그대로 둬.

확인: 직접 자료 호출이 있었다면 서버 함수로 바뀌고, 없었다면 파일 변경 없이 '없음'이라고 알려야 합니다.

## 만들기 2: 제작 2

A의 메모 읽기·추가·수정·삭제가 서버 함수에서 되는지 먼저 확인해 줘. 그다음 학습용 메모 테이블의 PUBLIC·anon·authenticated 직접 권한을 거두는 SQL 한 묶음과 적용 전후 권한 확인 방법을 제안해 줘. 다른 테이블은 건드리지 마. 내가 검토해 학습 DB에서 실행할게. 서버 함수의 로그인·소유자 검사와 서버 전용 설정은 유지해. 쿼리 없는 원본 자료 HTTPS 경로를 aleph.config.json의 originalApiUrl에 적어 줘.

확인: 화면의 A 정상 동작은 유지되어야 합니다. 원본 직접 요청은 심판이 anon 키로 확인합니다.
