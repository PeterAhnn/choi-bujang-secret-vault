# 2단계 팝업 프롬프트 원문

출처: https://aleph-omega.vercel.app/defense 로그인된 상황실 → 2단계 창
확인일: 2026-10-06 (한국 시간)
복사 방식: 현재 팝업에 표시된 각 문단의 원문 문자열을 읽어 줄바꿈과 함께 보관했다. 복사 버튼의 클립보드 결과는 확인되지 않아 사용하지 않았다.

아래 다섯 개는 화면의 실행 순서다. 오류·되돌리기 두 개는 해당 상황이 생길 때만 사용한다. 보관 사실과 실행 완료는 다르며, 현재까지 수행을 원문 그대로 실행한 것으로 소급하지 않는다.

## 1. 이어받기

```text
이 폴더는 1단계에서 만든 같은 자료실이야. 이번에는 2단계 「자료를 코드 밖으로 옮깁니다」를 할 거야. AGENTS.md와 README.md, 폴더 구조, git 상태, git log -1을 읽고 README의 단계 기록이 마지막 커밋과 맞는지 대조해 줘. 어긋나면 먼저 알려 줘. 현재 기능을 다섯 줄 이내로 요약하고 다른 작업은 보존해. 아직 아무 파일도 고치지 마.
```

## 2. 만들기 1: 제작 1

```text
현재 data.json의 가상 메모 세 개를 학습용 Supabase 테이블로 옮길 SQL 파일 하나를 만들어 줘. owner_id uuid 칸을 미리 두되 auth.users 외래키는 걸지 마. 테이블은 RLS를 켜고 anon·authenticated에는 자료 읽기 권한을 주지 마. 기존 공개 data.json에는 메모를 남기지 마. 실제 키는 요구하지 마.

확인: SQL Editor 실행 뒤 owner_id 칸과 RLS를 확인하고 새 정적 파일·GitHub 최신 파일에 가상 메모 문장이 없어야 합니다.
```

## 3. 만들기 2: 제작 2

```text
화면이 Vercel의 api 폴더에 둔 서버 함수를 통해 같은 가상 메모 네 건을 읽게 바꿔 줘. 함수는 SUPABASE_URL과 서버 전용 SUPABASE_SECRET_KEY를 환경변수에서 읽어. 키를 브라우저 파일·응답·로그에 넣지 마. 아직 함수는 공개 주소라는 약점도 README에 적어 줘.

확인: 화면에는 네 카드가 보이지만 /data.json을 열면 메모가 없어야 합니다. 공개 키 요청은 심판이 확인합니다.
```

## 4. 만들기 3: 제작 3

```text
현재 배포 파일과 GitHub 최신 파일에서 가상 메모 문장을 검색하는 확인 절차를 README에 적어 줘. 옛 공개 커밋과 옛 배포가 남는 한 과거 노출은 해소됐다고 쓰지 마.

확인: 검색 결과와 공개 API의 남은 약점을 각각 기록합니다.
```

## 5. 제출 전 확인

```text
이번 변경을 「2단계 저장점」으로 커밋해 줘. 그다음 npm run bundle을 실행해 제출 묶음 JSON과 요약을 보여 줘. 오류가 나면 첫 오류만 고쳐 줘.
```

## 6. 막혔을 때 넣을 프롬프트

```text
2단계 「자료를 코드 밖으로 옮깁니다」에서 [제작 번호]를 실행했는데 기대와 달라. 기대한 결과: [ ]. 실제 화면/첫 오류: [ ]. 비밀값을 지운 뒤 원인 후보를 두세 개 적고, 가장 가능성 높은 하나만 최소한으로 고쳐 줘. 다른 기능은 건드리지 마. 수정 뒤 직접 확인할 방법을 알려 줘.
```

## 7. 되돌려야 할 때

```text
2단계 변경 때문에 동작이 깨졌어. 먼저 git status와 diff로 이번 단계 변경과 다른 변경을 구분하고, 사라질 내용을 보여 줘. 다른 변경과 DB 자료는 보존해. 직전 작동 커밋으로 이번 단계 파일만 안전하게 되돌리는 방법을 제시하고, 확인받은 뒤 실행해 줘. reset --hard는 쓰지 마.
```
