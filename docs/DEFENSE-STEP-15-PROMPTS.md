아래는 현재 단계 화면의 공식 과제 안내야. 위 보충 설명과 충돌하면 구현 전에 차이를 알려 줘.
목표: 내 접속 기록(kind: access)과 저장된 XDR 경보(kind: xdr)를 시각·근거·규칙·상태와 함께 보여 주고, 필터와 상세 보기를 만듭니다.

고칠 파일: renderEvents. 필요하면 같은 파일 안에 필터 상태를 둡니다.

받는 값: renderEvents({ status, mode, data?, error? }), data 는 기록 배열입니다. - 기록: { id, kind, at, appId, summary, evidence:[{id,text}], rules:[{id,text}], state:{access,session,device}, supportedActions:[] } - state 의 세 값은 따로 표시합니다. access: allowed·denied·unknown, session·device 는 13단계와 같습니다.

어디까지 보이는가(관측 범위): - 이 목록은 앱 서버가 내 SDP 감사 기록에서 현재 등록 정보와 맞춰 본 내 기록입니다. 전체 로그도, 다른 학생 기록도 아닙니다. - 최근 40건까지만 옵니다. 더 있으면 제공 화면 위쪽에 전체 건수와 생략된 건수, 확인 시각이 함께 보입니다. 이 확인 범위 문구는 제공 화면이 보여 주며, 학생 함수에는 목록만 전달됩니다. - XDR 경보는 서버가 이미 저장한 경보만 나옵니다. 화면을 열 때 새로 탐지하지 않습니다. - 지금 등록 정보와 맞출 수 없는 옛 기록에는 앱 ID 가 비어 있을 수 있습니다(appId 없음). 지난 세션·기기의 상태는 확인 불가(unknown)로 옵니다. 정상으로 바꾸지 않습니다. - 지금 실제 목록의 supportedActions 는 비어 있습니다. 비어 있으면 조치 버튼을 만들지 않습니다. 15·16단계 자동 확인이 연결되지 않은 조치를 넘겨 주는 경우에만, 16단계에서 요청을 보내지 않는 비활성 안내 버튼을 상세 안에 둡니다.

상태별 표시: | 상황 | 보여 줄 것 | |---|---| | ok, 기록 있음 | 시각 순 목록, 종류·앱·요약. 기록을 누르면 근거·규칙·세 상태 | | ok, 빈 배열 | 표시할 기록이 없음 | | error | 실패. 빈 목록과 다르게 | | CONTRACT_MISMATCH | 확인 불가. 이전 목록을 지움 |

AI 에게 붙여 넣을 프롬프트: student/extension.mjs 의 renderEvents 를 구현해 줘. 앞 단계 함수는 그대로 둬. 입력은 { status, mode, data?, error? } 이고 data 는 기록 배열이야. 기록 하나는 { id, kind, at, appId, summary, evidence:[{id,text}], rules:[{id,text}], state:{access,session,device}, supportedActions } 야. - 목록은 at 기준 최신순으로 보여 줘. 각 행에 data-student-event-id 속성으로 event.id 를 붙이고, 사건 ID·시각·종류·앱·summary 를 글자로 적어. 시각은 at 원래 값이나 한국 시각으로 읽을 수 있게, 종류는 접속 기록인지 XDR 경보인지 알아볼 수 있게(예: access=접속, xdr=XDR 경보), 앱은 appId(없으면 앱을 확인할 수 없다는 것)로 적어. - 필터 선택 상자 세 개를 만들어. 접근 가능한 이름(label 또는 aria-label)은 "기록 종류", "업무 앱", "접속 상태" 로 하고, 전체 값은 all, 나머지 값은 원래 kind·appId·state.access 값으로 해. 서버에 다시 묻지 말고 받은 배열 안에서 걸러. - 행마다 상세 버튼을 두고 접근 가능한 이름을 "<event.id> 상세" 로 해. 상세 영역에는 data-student-event-detail 속성으로 event.id 를 붙여. - 상세에는 사건 ID 와 appId, evidence 의 id 와 text, rules 의 id 와 text, state 의 access·session·device 세 값의 원래 값과 한국어 설명을 모두 보여 줘. unknown 은 "확인 불가(unknown)". - 표식만 붙여서는 통과하지 않아. 실제 글자와 동작이 맞아야 해. - 빈 배열이면 기록이 없다는 것을, error 면 기록을 불러오지 못했다는 것과 message 를 보여 줘. 기록이 없는 화면이 실패처럼, 실패 화면이 빈 목록처럼 읽히면 안 되고 두 화면은 달라야 해(예: "표시할 기록이 없습니다", "기록을 불러오지 못했습니다: "). - 새 자료가 오면 이전 목록과 상세를 모두 지우고 다시 그려. - 기록 글에 <b> 같은 글자가 있어도 글자 그대로 보이게 textContent 만 써. - 실제 조치 버튼은 만들지 마. 연결되지 않은 조치 안내는 16단계에서 다뤄.

스스로 확인: 1. 기록이 여러 개·없음·실패일 때 화면이 각각 다르게 보이는지 봅니다. 2. 필터를 바꾸면 목록이 맞게 줄어드는지 봅니다. 3. 상세에서 세 상태가 따로 보이는지, unknown 이 확인 불가로 보이는지 봅니다. 4. 다시 불러오기 뒤 옛 상세가 남지 않는지 봅니다.

필수 확인 항목: student-source-changed, event_scope, event_time, event_filter, event_detail, events-refresh-replaces, events-empty-error-distinct. AI가 제출한 커밋의 코드를 위 항목과 대조해 판정합니다. 실제 화면에서의 동작은 아래 안내에 따라 직접 확인합니다.
