## 승인 범위와 기준선

사용자는 13단계 판정을 다시 확인하고 통과했으면 결과 정리 후 14단계 원문을 보여 주며 이어서 진행하도록 요청했다. 13단계는 커밋 9cb49a313aa7d064be975733852254237712ee38로 필수 5항목 모두 공식 통과했다. 기존 미추적 사본 20개와 1~12단계·XDR·DB·배포를 보존한다. 외부 문의는 계속 보류한다.

## 원문과 계약 대조

원문은 DEFENSE-STEP-14-PROMPTS.md에 화면 그대로 보관한다. 채팅에도 상세 프롬프트 전체를 먼저 표시했다. 로컬 STUDENT_PROMPTS.md의 이전 확인 안내는 네 판정 실제 재현·서버 중지를 요구하지만, 최신 포털은 실제 반환 결과만 확인하고 네 판정을 만들기 위해 정책·인증을 바꾸지 않도록 안내한다. 최신 포털을 따른다. 상태별 분기는 별도 모의 입력으로 검사한다.

현재 renderDecision은 대기 문자열만 반환한다. 제공 app.js의 studentData('decision')가 snapshot(state.access)와 appId를 전달한다. 제공 버튼이 /api/access로 요청한 뒤 loading 및 ok/error 상태에서 학생 함수를 다시 호출한다. renderStudent가 반환 DOM으로 이전 표시를 교체한다. 학생 함수에서는 새 요청을 만들지 않는다.

## 작업 스텝

1. 13단계 결과 기록과 14단계 원문·공통 규칙·계약을 대조한다.
2. renderIdentity와 다른 함수를 보존하고 renderDecision만 구현한다.
3. 상태·판정·모드·이유·시각·이전 값 교체를 모의 입력과 실제 로컬 화면에서 구분해 검사한다.
4. 사용자 직접 확인 후 이번 변경만 커밋하고 공식 원문으로 제출해 실제 판정을 확인한다.
