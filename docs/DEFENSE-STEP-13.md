## 원문 순서와 해석 차이

1. 승인된 폴더·규칙 준비를 먼저 수행했다.
2. 첫 실행 요청 원문을 채팅에 표시하고 파일·Git·실행 방법을 읽기만 했다. 안내를 다시 붙여 넣으라는 대기는 이미 승인된 포털 직접 읽기로 대신했다.
3. 13단계 상세 프롬프트와 그 안의 공식 안내를 채팅에 표시했다. 옮겨 적는 과정에서 한 글자 오타가 있어 바로 해당 원문을 다시 표시했다. 보관 문서는 화면에서 직접 추출한 원문이다.
4. 현재 함수와 입력·반환 계약을 확인한 뒤 renderIdentity만 구현했다.
5. 문법·모의 검사·실제 화면 검사를 수행하고 사용자 직접 확인을 요청했다. 실제 제출 승인과 사람의 화면 관찰을 구분한다.

로컬 IMPLEMENTATION_CONTRACT.md의 과거 AI 판정 설명과 STUDENT_PROMPTS.md의 이전 상태 번역은 현재 포털과 다르다. 수정 전 사용자에게 차이를 알렸으며 현재 포털의 필수 AI 코드 판정과 정확한 한국어 상태명을 적용했다. 제공 문서는 덮어쓰지 않았다.

현재 포털에는 사용자·장애 상태를 임의로 만들지 말라는 안내와 사용자 값 변경·서버 중지 확인 안내가 함께 있다. 사용자 값 변경은 별도 모의 입력으로 검사하고, 서버 중지는 이번 작업에서 시작한 로컬 예제 서버 한 개에만 수행했다. 운영 사용자·DB·인증·권한을 조작하지 않았다.

## 구현 범위

- 코드 변경: on-client/student/extension.mjs의 renderIdentity({ me, devices, sessions })만 구현했다.
- 세 입력의 loading/ok/error와 mode를 독립적으로 표시했다. 연결 없음·예제·확인 불가를 로딩·오류 상태에서도 표시한다.
- 사용자 label/id, 현재 기기 label/id/status, 세션 id/status와 기기·세션 목록을 입력값에서 읽는다. 알 수 없는 값은 확인 불가로 표시한다.
- 기기: 보안 기준 충족 / 보안 기준 미충족 / 확인 불가. 세션: 활성 / 만료 / 철회됨 / 확인 불가.
- 매 호출마다 createElement/textContent로 DOM 요소 하나를 생성해 반환한다. 제공 앱의 replaceChildren가 이전 학생 영역을 교체한다. 별도 서버 요청·자동 재시도를 추가하지 않았다.
- 독립 정적 검토에서 실제 결함을 발견하지 못했다. 제공 원본 56개 중 55개가 동일하고 나머지 한 파일도 renderIdentity 밖은 동일함을 확인했다.
