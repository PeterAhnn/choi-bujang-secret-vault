# AGI 시대의 보안 Agent 만들기: 13~22단계

2026-10-19 사용자 승인으로 작성한 작업 규칙이다. 공식 시작 틀의 제공 파일이 아니며 학생 구현·제출 요구사항을 추가하지 않는다.

## 범위와 우선순위

- 이 파일은 on-client 하위에 적용한다. 기존 저장소 루트가 Git 루트다. origin과 이전 1~12단계·XDR·DB·배포·다른 변경을 보존한다.
- 현재 로그인된 포털의 단계 원문과 사용자 지시를 먼저 읽는다. 로컬 문서와 다르면 차이를 알리고 최신 공식 안내에 근거해 처리한다. 전체 원문·사용한 프롬프트·실제 결과를 구분해 기록한다.
- 사용자가 승인한 계획 안에서 직접 실행한다. 구현 전 프롬프트 원문을 보여 주고 작은 단위로 변경·검증·보고한다. 승인된 범위의 도구 실행을 사용자에게 떠넘기지 않는다. 비밀 입력과 본인의 실제 확인·판단만 요청한다.
- 이전 R5의 고정 제목·100점·bundle·alephEvidence·observed·decider/detect 계약은 여기에 적용하지 않는다. AI 과제 T01~T11의 양식도 가져오지 않는다.

## 구현 경계

- 13단계 앱 코드 수정은 student/extension.mjs의 renderIdentity 함수 하나다. createStudentView와 제공 앱의 호출·교체 계약을 먼저 읽고 다른 함수의 기본 문구를 유지한다.
- 14단계 앱 코드 수정은 같은 파일의 renderDecision 함수 하나다. 13단계의 renderIdentity를 그대로 보존한다. 입력은 { status, mode, data?, error?, appId }이며 data는 { appId, decision, reason, checkedAt }이다. 요청은 제공 버튼이 보내므로 학생 함수에 요청·자동 재시도를 추가하지 않는다.
- 14단계는 idle/loading/ok/error를 나누고 allow/deny/challenge/unknown을 한국어 뜻과 코드로 표시한다. 목록 밖 판정은 확인 불가(unknown), 오류는 요청 실패이며 거부 판정이 아님을 표시한다. 판정 이유·시각·대상 앱을 표시하고 예제·연결 없음·확인 불가 모드를 유지한다.
- 14단계 실제 확인은 현재 반환 결과와 키보드 조작을 확인한다. 네 판정을 만들기 위해 정책·인증을 변경하지 않는다. 다른 분기는 별도 모의 입력으로 검사하며 실제 연결 결과와 구분한다.
- 15단계는 renderEvents만 구현하고 13·14단계 함수를 보존한다. 받은 배열을 복사해 at 최신순으로 정렬하며 추가 요청 없이 kind·appId·state.access 원래 값과 all로 필터링한다. 선택 상자의 접근 가능한 이름은 기록 종류·업무 앱·접속 상태다.
- 각 행의 data-student-event-id와 <event.id> 상세 버튼, 상세의 data-student-event-detail을 실제 내용·동작과 연결한다. 상세에 사건·앱 ID, 근거·규칙의 id/text, 접속·세션·기기 상태의 뜻과 코드를 따로 표시한다. 없는 앱은 확인 불가, unknown은 확인 불가(unknown)로 표시한다.
- 15단계는 새 호출에서 이전 목록과 상세를 교체한다. 빈 배열·조회 실패·계약 불일치를 구분하고 오류 후 이전 목록을 남기지 않는다. 제공 화면의 범위 수치를 추정하지 않으며 지원 조치 버튼은 추가하지 않는다. 모의 검사·예제 앱·실제 계정 연결·사용자 직접 확인·공식 판정을 구분한다.
- public/app.js, src, 제공 서버·화면·판정 코드·인증 설정은 수정하지 않는다. 이름을 바꾼다는 이유로 제공 파일명·앱 제목을 임의 변경하지 않는다.
- renderIdentity 입력은 { me, devices, sessions }, 각각 { status, mode, data?, error? }이다. 없는 계약·요청·사용자·권한을 만들지 않는다.
- 세 입력의 loading/ok/error를 각각 처리하고, demo/disconnected/unknown은 loading·error 때도 표시한다. 오류가 나면 이전 사용자 값을 지운다. 새 입력으로 화면을 교체한다.
- 현재 포털의 번역을 사용한다: compliant=보안 기준 충족, noncompliant=보안 기준 미충족, unknown=확인 불가; active=활성, expired=만료, revoked=철회됨.
- 공식 STUDENT_PROMPTS.md의 공통 문구 규칙도 단계별 안내와 함께 대조한다. 기기·세션의 현재 상태와 목록 상태는 한국어 뜻과 전달받은 원래 코드를 함께 표시한다. 예: 보안 기준 미충족(noncompliant), 만료(expired). 한국어 뜻만 검사해서 코드 누락을 놓치지 않는다.
- document.createElement와 textContent로 DOM 요소 하나를 반환한다. innerHTML로 입력을 해석하지 않는다. 색상 외 텍스트로 상태를 구분하고 기존 키보드 조작을 보존한다.
- 비밀번호·토큰·개인키·서버 키를 요청하거나 코드·대화·Git·캡처·제출물에 남기지 않는다.

## 검증과 제출

- 코드 검토, 별도 모의 데이터 검사, 실제 로컬 화면 검사, 사용자 직접 확인, 공식 AI 판정을 각각 기록한다. 확인하지 않은 검사는 미확인으로 남긴다.
- demo는 예제 자료이고 disconnected는 연결 없음이다. 연결 상태 표시를 악성코드 검사·치료·실제 운영 연결 성공으로 설명하지 않는다. 13단계에서 외부 AI·SDP·Supabase 연결을 추가하지 않는다.
- 상태 전환은 모의 데이터로 확인한다. 실제 사용자·장애 상태를 임의로 조작하지 않는다. 서버 중지 검사는 이번 작업에서 시작한 로컬 앱 프로세스에만 수행한다.
- 첫 오류와 공식 판정문을 먼저 확인하고, 공식 입력과 실제 코드에서 원인을 재현한 뒤 최소 수정한다. 추측한 검사를 통과시키려고 입력이나 제공 코드를 바꾸지 않는다. 같은 오류를 근거 없이 반복 제출하지 않는다.
- 현재 13단계 필수 항목은 student-source-changed, three-menus, student-identity-updates, student-failure-visible, identity-after-reload다. 공개 단계가 바뀌면 최신 원문을 다시 확인한다.
- 이번 단계 파일만 명시적으로 커밋한다. 원문 전달은 커밋된 파일만 포함한다. 실제 확인한 40자리 해시와 저장소를 사용한다. 제출 접수·검토 중·확인 불가·불통과·통과를 구분한다.
- 결과가 나오기 전 제출을 반복하지 않는다. 공식 필수 항목 전체 통과와 서버 기록을 확인한다. 잠금과 반 공개 상한은 우회하지 않는다.
- 외부 문의는 사용자가 보류했다. 실제 유료 AI 호출·운영 보안 조치는 임의 실행하지 않는다. 복구 시 이번 단계 변경만 구분하며 reset --hard·일괄 삭제·강제 push를 사용하지 않는다.
